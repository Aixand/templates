# First implementation: capabilities and limits

This is the retained schema-1 surface. [Revision 2](V2.md) adds workspace
components, independent products/groups, portable lifecycle operations, runtime
bootstrap, and release handoff without changing existing schema-1 formats.

The vendored helper is `files/scripts/dev/`. Copy it with the platform wrapper
and an adapted profile following [SETUP.md](SETUP.md).

## Capabilities

- Language-independent command dispatch, capability reporting, structured argv
  hooks, a custom profile, and a read-only prerequisite inspection.
- Python development through locked uv environments; pure-Python project wheel
  and source builds, hashed dependency wheelhouses, offline installation, and
  independent consumer/CLI verification.
- Cargo development/checks/tests, selected package/workspace builds, verified
  `.crate` packaging, independent Rust consumers, native single-binary payloads,
  resources, and artifact inventories.
- Unix managed prefixes, ownership checks, private versioned Python environments,
  common active selection, recoverable activation journals, explicit artifact
  upgrades, stateless rollback, retention planning, pruning, and uninstall.
- Versioned configuration, release, and selection-receipt schemas. A prefix
  ownership marker identifies the product/origin; each payload binds its complete
  release manifest through a digest and its own ownership receipt.
- CI and publishing workflow examples for PyPI, selected Cargo library crates,
  and native GitHub Releases, including published-artifact confirmation adapters.

The template's own CI workflow is a repository file awaiting a real GitHub run.
Publishing examples are opt-in source files; they have not published a package.

## Initial supported surface

| Operation | Python library | Python tool | Rust library | Rust CLI | Custom |
| --- | --- | --- | --- | --- | --- |
| Help/doctor | Yes | Yes | Yes | Yes | Yes |
| Develop/check/test/build | Declared Python commands + uv | Declared Python commands + uv | Cargo | Cargo | Declared commands |
| Package | Wheel, sdist, wheelhouse | Wheel, sdist, wheelhouse | Selected verified crate | Native host/selected target archive | Explicit package hook/artifact list |
| Verify with install proof | Fresh environment/API | Fresh environment/CLI | Independent Cargo consumer | Disposable native payload | Structural verification only |
| Managed install/reinstall/upgrade | Use package manager | Unix | Unsupported | Unix | Unsupported |
| Rollback | Consumer policy | Unix, stateless only | Unsupported | Unix, stateless only | Unsupported |
| Prune/uninstall | Package manager | Unix, explicit stopped declaration | Package manager | Unix, explicit stopped declaration | Unsupported |
| Publication | Selected PyPI example | Selected PyPI example | Selected crates.io example | Selected GitHub download example | Project adapter required |

`publish` in the generic helper is deliberately unsupported: publication uses an
explicit destination-specific workflow/adapter. No ordinary helper operation
publishes or changes a production stable pointer.

## Boundaries still requiring implementation or qualification

- Native Windows managed activation; Windows and macOS native test runs. The
  PowerShell wrapper is provided, but its presence does not establish execution
  qualification.
- Public installer/catalog integration and machines without a helper interpreter.
  This developer helper requires Python 3.11+. Python adapters also require uv;
  Cargo source operations require the project's Rust toolchain. A Rust artifact
  installation does not compile the product or require Rust for its smoke test.
- Coordinated local/Git Python dependency overrides in packaged wheelhouses and
  Cargo path dependencies outside the selected project root. V1 fails explicitly
  for these inputs. Development can still use a project's declared uv sources.
- Native project Python wheels, editable global tool installs, enabled-extra
  variants, multi-binary bundles, embedded Python, and system package installers.
- Registry identity/setup and actual publication jobs. The supplied workflows
  require real ownership, environments, allowed refs, and Trusted Publishers.
- Registry credential/private index adapters beyond the explicit public examples.
- Stateful rollback/migrations and automatic process/runtime garbage collection.

Native target triples describe the build target. Project maintainers must still
choose and qualify minimum OS/libc versions and required system libraries before
advertising a release target. The example Ubuntu runner is not a claim of broad
Linux ABI compatibility.

Static checks bind the local package to its supplied manifest and checksum list.
An attacker able to replace all three can forge those local hashes. Authenticate
public downloads through an expected trusted release source and verified
provenance; public trust/bootstrap integration is separate work. The native
GitHub workflow binds its confirmation to the manifest from the verified run.

## Validation entry points

```sh
./dev.sh develop
./dev.sh check
./dev.sh test
```

Tests render actual package fixtures outside the repository. They exercise
consumer/resource behavior, rejected input, successful retry, concurrent mutation,
activation recovery, retained versions, and preservation of synthetic user data.
External publishing and deployed repository settings are not inferred from them.
